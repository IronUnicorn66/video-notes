# 官网主页精简设计

## 目标

把中英文官网主页从约 5 个桌面视口压缩到 2–3 个视口，让首次访问者按“问题、用法、价值”的顺序理解产品，并能直接下载或查看安装方式。

## 方案比较

### 方案一：三段式叙事（采用）

主页只保留问题、用法、价值三个内容段落。功能、隐私、支持范围和安装信息按访问决策合并进对应段落。

优点：信息顺序与用户提出的三个问题一致；重复最少；中英文容易保持同步。代价：详细功能参数不再逐项展示，访问者需要从 GitHub 或隐私页了解补充信息。

### 方案二：保留现有模块并缩短文案

继续保留能力数字、功能卡、本地数据流、安装和支持模块，只缩短标题与正文。

优点：现有结构改动少。代价：页面仍接近 4 屏，信息重复仍然存在。

### 方案三：单屏产品卡片

将全部内容压成首屏截图、三条卖点和下载按钮。

优点：最短。代价：无法完整回答怎样使用，手动安装测试版的门槛也会变高。

## 信息结构

### 导航

保留“怎样使用 / How it works”“价值 / Benefits”“安装 / Install”“隐私 / Privacy”、语言切换和 GitHub。安装入口指向第二屏中的紧凑安装说明。

### 第一屏：解决什么问题

用一句主标题说明核心场景：视频中的重点容易在继续播放后失去上下文。正文说明插件把想法、时间点、截图、字幕和语音放到同一条时间线上，并可导出 Markdown。

右侧继续使用现有产品界面示意或截图。保留下载和查看用法两个主操作，同时将“本地保存、开源、无需账号”作为简短信任信息。

### 第二屏：怎样使用

把流程压缩为四步：安装扩展、打开侧栏、记录重点、导出整理。安装测试版说明与下载按钮合并到本段底部，使用三条短说明覆盖下载解压、打开扩展管理页、加载解压目录。

### 第三屏：能带来什么价值

使用三张卡片表达结果：

- 观看节奏更连续：输入时自动暂停，保存后续播。
- 笔记保留语境：时间点、标记前字幕、截图和语音跟随每条笔记。
- 资料由用户掌握：本地处理并导出 Markdown、图片与录音，在现有笔记工具中继续整理。

支持 YouTube 与哔哩哔哩、本地优先和隐私政策入口合并到本段结尾，不再单独占用整屏。

## 中英文一致性

中英文页面使用相同的元素顺序、锚点和卡片数量。英文采用自然表达，不逐字翻译中文。下载版本、链接、隐私入口和支持范围在两种语言中保持一致。

## 视觉与响应式

沿用当前米白、深绿和珊瑚色视觉语言，不引入新图片或脚本。桌面目标高度不超过 2700 像素（1440 × 900 下最多 3 个视口）。移动端允许自然增长，但信息仍保持三个主题段落，导航继续保留语言切换。

## 测试与验收

- 自动化测试确认中英文主页都有问题、用法、价值三个语义区，旧的详细功能区和能力数字区已移除。
- 自动化测试确认下载、隐私、GitHub、语言切换与无第三方脚本约束继续有效。
- 项目版本由 1.0.3 升级至 1.0.4，清单、包文件、锁文件、发布测试和当前发布文档保持一致。
- 在 1440 × 900 和 390 × 844 视口检查中英文页面，确认无横向溢出、导航可用、正文层级清楚。
- 运行完整测试套件和发布包检查。
