# 英文本地化设计

## 目标

为 Video Notes 扩展界面、产品官网和 GitHub README 提供完整英文入口，让英语母语用户能够安装、授权、记录、导出并理解数据处理方式，同时保留现有中文体验。

## 范围

- 扩展侧栏、麦克风授权页、用户可见状态提示、确认提示和导出 Markdown 固定文案提供简体中文与英文。
- Manifest 增加英文名称与描述，Edge 按界面语言显示对应商店元数据。
- 官网主页与隐私政策提供独立英文路径和英文界面截图。
- GitHub 默认 README 使用英文，独立中文 README 保留现有中文内容，两份文档互相链接。
- 当前发布版本从 `1.0.2` 升级到 `1.0.3`，同步 Manifest、包元数据、锁文件、发布测试和当前发布文档。
- 商店发布文档、开发验收清单和代码注释继续使用中文；验收清单中的当前版本信息需同步更新。

## 语言选择

扩展首次运行时读取 Edge 界面语言。以 `zh` 开头的界面语言选择简体中文，其余语言选择英文。侧栏顶部提供 `中文 / EN` 切换，用户选择保存在 `chrome.storage.local`，并在侧栏、麦克风授权页、后台处理和导出内容中复用。

官网中文路径为 `/` 与 `/privacy/`，英文路径为 `/en/` 与 `/en/privacy/`。首次访问且没有保存偏好时，页面读取浏览器语言并跳转到对应路径。语言链接保存用户选择，后续访问沿用该偏好。网站保持纯静态部署，只加载仓库内脚本和资源。

## 扩展架构

新增一个无浏览器依赖的语言核心模块，负责规范化语言代码、选择自动语言、读取语义化消息键和替换变量。中英文运行时字典集中维护，调用方传入当前语言，不让业务模块自行拼接两套文案。

新增扩展语言绑定模块，负责从 `chrome.storage.local` 读取偏好、监听偏好变化并把语言应用到当前页面。侧栏和麦克风授权页使用同一份绑定逻辑。静态 HTML 文案通过 `data-i18n`、`data-i18n-placeholder` 和 `data-i18n-aria-label` 标记更新；脚本动态生成的按钮、状态、错误提示和确认内容通过语言核心模块生成。

Manifest 的 `_locales/zh_CN/messages.json` 保留中文名称和描述，新增 `_locales/en/messages.json`。扩展运行时的手动选择独立于 Manifest 展示语言，因为浏览器只按 Edge 界面语言解析 Manifest 本地化资源。

导出 Markdown 根据扩展语言偏好选择固定标题、字段标签和空内容提示。用户输入、视频标题、字幕、转写和文件目录结构保持原内容。

## 官网与 README

中文官网保持现有文件位置。英文官网使用独立静态 HTML，结构与链接目标和中文页面一致，文案按英语母语表达重写。共享语言脚本只处理自动跳转和偏好保存，不在运行时替换整页正文。

英文主页和英文 README 使用新增的英文侧栏截图。中文官网与中文 README 继续使用现有中文截图。英文隐私政策覆盖本地存储、模型下载连接元数据、权限、保留、删除和联系渠道，与中文政策表达相同的数据处理事实。

`README.md` 成为英文默认入口，`README.zh-CN.md` 保存中文版本。两份文档顶部提供 `English | 简体中文` 链接，并使用各自语言的安装、使用、隐私、开发、支持和安全说明。

## 失败处理与兼容

- 扩展语言偏好缺失或无效时回退到自动语言；自动语言无法读取时回退到英文。
- 网站无法访问 `localStorage` 时仍按浏览器语言选择，语言链接继续作为普通链接工作。
- 缺少消息键时返回消息键，便于测试和开发阶段发现漏译。
- 已保存笔记和设置的数据结构不迁移，升级后可直接读取。
- 页面切换语言时重新渲染当前界面，避免部分组件保留旧语言。

## 验证

- 语言核心测试覆盖中文浏览器、英文浏览器、显式偏好、无效偏好、变量替换和缺失消息键。
- 侧栏相关测试覆盖英文静态文案、英文动态状态和语言偏好变化后的重新渲染。
- 导出测试覆盖相同笔记在中英文语言下生成对应固定标题，用户内容保持一致。
- Manifest 与发布包测试覆盖英文语言包和 `1.0.3` 版本一致性。
- 官网测试覆盖四个页面、互相切换链接、自动语言脚本、英文隐私要点和英文截图资源。
- 完整测试、构建、打包、ZIP 完整性和版本引用检查全部通过。
