# 笔记删除、清空与撤销历史设计

## 目标

为每个视频的笔记时间线增加单条删除、整段清空、撤销和反撤销能力。删除与清空必须先确认；新增时间点笔记、正文修改、前置字幕修改、删除和清空均可撤销。创建一个新视频会话、自动转写、排序、设置和导出不进入历史。

发布版本为 `0.3.0`。

## 用户交互

- 每张已保存笔记卡片增加“删除”按钮。
- 时间线工具栏增加“撤销”“反撤销”“清空”；“清空”紧邻“导出 ZIP”。
- 删除确认框显示笔记时间点，清空确认框显示当前视频的笔记数量，两者均说明操作可撤销。
- 清空当前视频是一个原子历史动作，一次撤销恢复清空前的全部笔记。
- 支持 `Cmd/Ctrl+Z` 撤销和 `Cmd/Ctrl+Shift+Z` 反撤销。正文、字幕或快速标记编辑框聚焦时，快捷键保留给浏览器原生文字编辑。
- 正在编辑、保存或录音时，删除、清空、撤销和反撤销不可用。
- 操作成功后刷新当前侧栏并显示简短提示；失败时保留原界面与历史状态并显示错误。

## 历史语义

每个视频会话维护独立的撤销栈和反撤销栈，并持久化到 IndexedDB，因此关闭侧栏或重启 Edge 后仍可使用。每个栈的有效历史上限按最近 50 个动作控制。

历史动作分为：

- `add-note`：一条文字或语音时间点笔记首次进入 `saved` 状态后记录。撤销会软删除笔记，反撤销会恢复笔记及其资产。
- `edit-body`：保存用户正文修改时记录修改前后的正文；规范化后没有变化则不记录。
- `edit-subtitle`：保存前置字幕修改时记录修改前后的字幕；内容没有变化则不记录。
- `delete-note`：记录被删除的单条笔记 ID；撤销恢复，反撤销再次软删除。
- `clear-session`：记录当时可见的全部笔记 ID；撤销整体恢复，反撤销整体清空。

执行新动作后清空反撤销栈。自动转写对已存在笔记的后台更新不产生历史动作；若笔记在转写期间被软删除，迟到的转写结果可以继续写入隐藏记录，撤销删除后显示最新结果。

## 数据模型与事务

IndexedDB 数据库版本升级，并增加 `history` 对象仓库。每个视频会话保存一个历史记录：

```js
{
  sessionId,
  undo: [action],
  redo: [action],
  updatedAt,
}
```

笔记增加可选的 `deletedAt` 字段；字段存在时，普通列表、导出和待转写扫描都忽略该笔记。内部历史操作可以按 ID 读取并恢复软删除记录。

所有可撤销写操作都在包含 `notes` 与 `history` 的同一个 IndexedDB 读写事务中完成。撤销和反撤销先验证动作仍适用于当前状态，再在同一事务内变更笔记和两个历史栈；事务失败时两者都不改变。

新增笔记的历史记录在笔记完成保存时写入。文字笔记在提交正文时记录，语音笔记在录音及资产持久化成功、笔记进入 `saved` 状态时记录。创建视频会话本身不记录。

## 软删除与永久清理

删除、清空或撤销新增笔记时，只设置 `deletedAt`，并保留截图、录音和转写数据，以保证可恢复。

当历史超过 50 个动作或新动作清空反撤销栈后，系统检查已软删除且不再被任何撤销或反撤销动作引用的笔记。只有这些不可恢复记录才会从 `notes` 永久删除，并同时删除其 `screenshotKey` 与 `audioKey` 资产。模型、设置、权限、其他视频会话及其笔记不受影响。

## 后台接口

侧栏通过后台消息执行所有变更：

- `DELETE_NOTE`
- `CLEAR_SESSION_NOTES`
- `UNDO_NOTE_ACTION`
- `REDO_NOTE_ACTION`
- `GET_ACTIVE_STATE` 返回当前会话的 `canUndo` 与 `canRedo`

现有 `COMMIT_TYPED_NOTE`、语音保存完成、`UPDATE_NOTE_BODY` 和 `UPDATE_NOTE_SUBTITLE` 改为调用带历史事务的仓库方法。后台完成操作后继续使用现有按标签页隔离的刷新机制，不广播或切换其他窗口的侧栏上下文。

## 侧栏状态

侧栏用一个独立控制器统一计算删除、清空、撤销和反撤销按钮的可用状态。依赖输入包括当前保存笔记数量、`canUndo`、`canRedo`、正文/字幕编辑状态、保存状态和录音状态。

确认框使用扩展包内的原生 `<dialog>`，包含标题、说明、取消和确认按钮。一次只允许一个确认动作；关闭或取消不会写入历史。

## 错误处理与并发

- 同一侧栏在请求进行时禁用所有历史操作，防止重复提交。
- 后台事务串行应用每个会话的历史变更；过期、缺失或状态不匹配的动作返回可见错误，不静默覆盖数据。
- 转写已经开始时允许软删除；待转写扫描不再启动已删除笔记的新任务。
- 删除或清空不会影响当前未完成的快速标记或录音，因为这些操作在编辑、保存或录音忙碌时不可用。

## 测试与验收

- 历史纯逻辑测试覆盖五类动作、50 条上限、撤销后新动作清空反撤销栈，以及无变化编辑不记录。
- IndexedDB 测试覆盖写操作与历史的原子性、软删除过滤、跨实例/重启恢复、清空整体恢复、永久资产清理和失败不部分提交。
- 后台测试覆盖新增文字/语音笔记记录历史、修改、删除、清空、撤销、反撤销以及转写中的软删除。
- 侧栏测试覆盖按钮状态、确认/取消、快捷键输入隔离、请求期间禁用和操作失败提示。
- 全量 `npm test`、打包、ZIP 完整性与 Manifest `0.3.0` 版本检查必须通过。
- Edge 实机验收由用户执行，覆盖新增、修改、删除、清空、跨重启撤销以及截图/录音资产恢复。
