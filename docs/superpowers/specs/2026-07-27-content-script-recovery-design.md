# 内容脚本连接自愈设计

## 1. 背景与根因

侧栏初始化时通过后台向当前视频标签页发送 `GET_PAGE_CONTEXT`。后台当前直接调用 `chrome.tabs.sendMessage()`，默认目标标签页已经存在当前扩展版本的内容脚本接收器。

扩展安装、更新或开发环境重新加载后，已经打开的 YouTube、哔哩哔哩页面不会自动获得新版本内容脚本。此时侧栏请求会收到 `Could not establish connection. Receiving end does not exist.`，刷新流程把错误文本写入当前视频区域，并禁用快速标记输入框和语音按钮。刷新视频页面后功能恢复，说明故障位于后台与内容脚本之间的消息边界。

## 2. 目标

- 当前视频标签页缺少内容脚本接收器时，后台自动恢复连接并重试原消息。
- 用户无需刷新视频页面即可使用快速标记。
- 同一标签页的并发请求只触发一次脚本注入。
- 仅恢复“接收端不存在”错误，其他通信或业务错误继续向调用方传播。
- 保持当前声明式内容脚本配置，正常页面加载路径不变。

## 3. 方案选择

采用按需注入与单次重试：后台首次发送失败后识别接收端缺失错误，通过已有 `scripting` 权限向目标标签页注入构建产物 `content.js`，随后重试同一消息。

没有选择启动时扫描全部标签页。按需方案只处理实际使用侧栏的标签页，减少启动工作，也覆盖扩展运行期间出现的接收端缺失。没有采用只显示“请刷新页面”的提示，因为该方案仍会中断用户当前操作。

## 4. 组件与职责

新增一个独立的标签页消息模块，职责包括：

- 识别 Chromium 返回的接收端缺失错误。
- 调用 `chrome.tabs.sendMessage()` 发送消息。
- 使用 `chrome.scripting.executeScript()` 注入指定内容脚本。
- 按标签页记录正在进行的注入任务，让并发恢复共享同一个 Promise。
- 注入结束后清理临时任务记录。

后台只负责用浏览器 API 创建消息发送器，并保留现有 `sendToTab(tabId, message)` 调用接口。内容脚本、侧栏和业务消息格式不改动。

## 5. 数据流

正常路径：

1. 后台向目标标签页发送消息。
2. 内容脚本返回业务响应。
3. 后台沿用现有响应校验并返回结果。

恢复路径：

1. 首次发送因接收端缺失而失败。
2. 消息模块检查该标签页是否已有注入任务。
3. 没有任务时创建注入；已有任务时等待同一任务。
4. 注入成功后重试原消息一次。
5. 重试响应进入现有业务校验。

## 6. 错误处理

- 首次发送出现接收端缺失：执行一次恢复。
- 首次发送出现其他错误：直接抛出，不注入脚本。
- 脚本注入失败：向侧栏传播注入错误，保留浏览器提供的具体原因。
- 注入后重试仍失败：传播第二次错误，不循环重试。
- 多个并发请求等待的注入失败：所有请求收到同一失败结果；任务记录会清理，后续操作可以重新尝试。

## 7. 测试设计

新增纯逻辑单元测试，使用可控的标签页消息和脚本注入替身验证：

- 首次发送成功时不注入脚本。
- 接收端缺失时注入 `content.js` 并重试原消息。
- 其他发送错误不触发注入。
- 同一标签页两个并发恢复只执行一次注入，两个原消息分别重试。
- 注入完成后清理并发状态，后续缺失可以再次恢复。
- 重试失败时不进行第二次注入。

完成后运行新增测试、全部测试和扩展构建。手动验收步骤为：保持视频标签页打开，重新加载扩展后直接打开侧栏，确认标题与输入框恢复；点击输入框，确认视频暂停并可保存或取消标记。

## 8. 改动范围

- 新增标签页消息核心模块及其单元测试。
- 修改后台消息发送接线，使用自愈发送器。
- 在验收清单补充扩展重载后无需刷新视频页的场景。

不修改页面标记逻辑、侧栏视觉样式、存储格式、权限清单或内容脚本声明配置。
