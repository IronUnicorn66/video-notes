# 课程中文地图与配套 skill 调研

调研及实现日期：2026-09-09。基于本仓库导出功能及原有个人 video-notes skill，配套版本现位于 [skills/video-notes/](../skills/video-notes/SKILL.md)。会员登录和插件内模型接入已暂缓，本次不实现。

## 推荐工作流

浏览器扩展负责采集课程原文、时间轴、用户批注和截图；导出 ZIP 后，使用仓库中的 video-notes skill 整理成 Markdown/Obsidian 笔记，并由同一次整理生成中文课程地图。这一阶段不需要插件登录模型账号，也不需要新增服务端。

配套 skill 已保留原有未导入文件识别、用户批注、附件整理、课程上下文与详细 AI 点评，并增加安全解压、全量原文阅读、中文分章和时间覆盖校验。安装脚本在替换已有 skill 前先备份。当前已验证合成导出与工具衔接，尚未用真实课程验收中文分章质量。

## 课程地图的具体形式

建议采用两级可点击目录：一级是章节主题，二级是章节内的概念、例子或推导。每个条目包含中文标题、开始与结束时间、一句话摘要和支撑它的原文 cue ID。点击开始时间打开原视频的相应时刻。在 Obsidian 中这种链接会打开视频页面；如果未来需要在插件当前播放器中原地跳转，需要增加目录导入与渲染功能。

以下仅为结构示例，不是任何真实课程的目录：

| 时间范围 | 中文主题 | 内容说明 |
| --- | --- | --- |
| 00:00–04:20 | 本讲问题与目标 | 为什么需要这个概念、它解决什么问题 |
| 04:20–16:10 | 核心定义与直觉 | 关键术语、假设及一个解释性例子 |
| 16:10–31:00 | 推导与应用 | 分步骤推导、适用条件和案例 |

字幕原有分块通常很短，不适合一条一句直接做课程目录。应完整阅读原文后按语义聚合，保留“章节 → 原始字幕”的可追溯关系。输出中文目录与摘要，并不要求先逐句翻译整节课；全文中文译稿可以作为另一个明确的输出需求。

## 已实现的 skill 流程

1. 安全检查 ZIP，优先读取 `export.json`，通过 `notesFile` 定位用户批注，通过 `transcript.jsonFile` 定位全量原文；兼容旧版 ZIP。
2. 核对课程 ID、实际语言、字幕数量与时间范围。无完整字幕时标注“局部材料”，不能按零散批注编造全课目录。
3. 按连续 cue 顺序串行阅读；长课程可分批读取，维护术语表与各批次摘要，给跨批次边界保留少量上下文。不能只总结有批注的片段或因长度只读开头。
4. 先生成章节候选，再合并重复主题并检查覆盖；每个章节的起止时间必须从引用 cue 的实际时间取得，不能让模型自行估计时间。
5. 在“我的批注速览”之后增加“课程中文地图（AI 整理）”，再按现有 skill 呈现时间点批注、截图、课程上下文及 AI 点评。保留现有概要、后续行动和待确认问题。
6. 通过渲染脚本生成 `课程地图.md` 与 `课程地图.json`，包含 `sessionId`、原文 SHA-256、中文标题、摘要、起止毫秒与 `cueIds`。脚本从原字幕计算时间，拒绝遗漏和重叠的 cue 范围；Markdown 初始标为“待复核”，由 agent 完成语义检查后标记已整理。当前没有插件回载入口。
7. 验证时间单调、时间不越界、引用 cue 存在、链接对应当前视频、原始数据未改动。字幕空白应明确标注；术语翻译不确定时保留英文并解释缺口。

## 难度与推进顺序

| 工作 | 难度判断 | 主要工作 |
| --- | --- | --- |
| 保留原文与时间的 ZIP 导出 | 低到中 | 复用已有字幕缓存，补充结构化文件和异常分支；已在本次实现 |
| 扩展现有 skill 生成中文地图 | 中 | 已实现主笔记识别、分批阅读约定、语义分章指引、归因与覆盖校验；真实课程质量待验收 |
| 把生成目录导回插件并点击定位 | 中 | 文件导入、课程身份校验、版本匹配、目录界面与播放器跳转 |
| 插件内一键运行模型 | 中到高 | 本机程序安装、通信、登录、任务取消恢复与版本兼容；本次暂缓 |

建议先用一节真实课程验证导出和 skill 的中文目录质量，再决定是否值得做插件内的导入或自动调用。实现效果的主要难点是分章与翻译质量、长课程覆盖和可追溯性；点击时间跳转可复用项目已有能力。

## 模型接入调研留档（暂不实施）

ChatGPT 订阅与 OpenAI API 是独立计费体系；持有会员不自动获得通用 API 额度。[OpenAI 计费说明](https://help.openai.com/en/articles/9039756-chatgpt-search)

Codex 官方支持 ChatGPT 登录以使用订阅权益，也支持单独按量计费的 API Key 登录。[Codex 身份验证](https://learn.chatgpt.com/docs/auth)

官方 app-server 提供面向自有产品的身份验证、对话、审批与流式事件接口。技术上可考虑“浏览器扩展 → 本机 Native Messaging 程序 → Codex app-server”的架构，这是基于两套官方接口提出的工程方案，本次未做实测。不要假设能够直接调用 ChatGPT 网页中的所有 Pro 模式；具体模型与额度要以 Codex 当前账号可用项为准。app-server 的 WebSocket 传输在当前文档中标记为实验性且不受支持；如将来做本机桥接，应优先评估 stdio，并固定兼容版本。[Codex app-server](https://learn.chatgpt.com/docs/app-server)、[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

Native Messaging 需要额外安装并注册本机程序，声明扩展权限与允许的扩展 ID，且有单消息大小限制。这使它适合先做个人本机实验；普通用户分发还要处理多平台安装与更新。因此本次采用导出后交给 skill 的工作流。
